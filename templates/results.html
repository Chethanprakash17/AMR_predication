Model Performance & Evaluation Results

This page presents the performance metrics and evaluation results of our XGBoost classifier for AMR risk prediction. The model was trained on MIMIC-IV data using a temporal train-test split to ensure realistic evaluation.

Training Framework Scikit-learn (Python)

Training & Evaluation Strategy

Temporal Train-Test Split

To simulate real-world deployment and test the model's ability to generalize to future patients, we used a temporal split rather than random sampling:

Dataset Time Period Sample Size Percentage
Training Set 2008 - 2017 ~24,500 admissions 70%
Test Set 2018 - 2019 ~10,500 admissions 30%
Why Temporal Split? Random train-test splits can leak information from future patients into training data. A temporal split ensures the model learns from historical data and is tested on genuinely unseen future patients, better reflecting real-world performance.

Cross-Validation

During model development, we performed 5-fold stratified cross-validation on the training set for hyperparameter tuning and model selection. Stratification ensures each fold maintains the same class balance (AMR positive vs. negative).

Metric Interpretation: While accuracy is intuitive, it can be misleading with imbalanced datasets. AUROC and recall are more informative for clinical applications where missing a positive case (false negative) has more serious consequences than a false alarm (false positive).

ROC Curve Analysis

Figure 1: Receiver Operating Characteristic (ROC) Curve - AUC = 0.82

The ROC curve plots the True Positive Rate (sensitivity) against the False Positive Rate (1 - specificity) across different probability thresholds. Key points:

  • AUC = 0.82: Values > 0.80 indicate strong predictive performance
  • Curve Position: The closer the curve to the top-left corner, the better
  • Baseline (diagonal): Represents random chance (AUC = 0.50)
  • Clinical Utility: Allows selection of optimal threshold based on risk tolerance

Threshold Selection

The default threshold is 0.50 (50% probability), but clinicians can adjust this based on context:

  • Lower threshold (e.g., 0.30): Increases sensitivity (fewer missed cases) at cost of more false positives
  • Higher threshold (e.g., 0.70): Increases specificity (fewer false alarms) at cost of more missed cases
  • ICU Setting: Lower threshold preferred to minimize missing AMR cases in critically ill patients

Why Recall (Sensitivity) Is Prioritized in ICU Settings

In our model, we prioritize recall (sensitivity) over precision. Here's why this matters:

❌ False Negative (Missed AMR Case)

High Clinical Risk:

  • Patient receives narrow-spectrum antibiotic
  • Pathogen is actually resistant
  • Treatment fails, patient deteriorates
  • Delayed appropriate therapy = worse outcomes
  • Potential consequence: Death

⚠ False Positive (False Alarm)

Lower Clinical Risk:

  • Patient receives broader-spectrum antibiotic
  • Pathogen is actually susceptible
  • Treatment is effective (though broader than needed)
  • Minor downside: contributes to AMR development
  • Consequence: Manageable
Clinical Imperative: In ICU settings with critically ill patients, it is safer to err on the side of caution. Missing an AMR case (false negative) can be fatal, while treating a susceptible case with broader antibiotics (false positive) is suboptimal but generally safe. Therefore, high recall is prioritized.
